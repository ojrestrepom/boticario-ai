# Tasks

Nota: cada grupo es un commit. El orquestador hace el commit al aceptar el grupo. Toda acción en Google Cloud (crear el secreto, roles, habilitar APIs), en GitHub (secretos, `push`, `gh`) la ejecutan el usuario o el orquestador con aprobación del usuario; las tareas lo marcan con «[usuario]» u «[orquestador]». Los pasos manuales de Google Cloud y GitHub (grupo 8) quedan documentados con comandos en `docs/deploy/cloud-run.md` (tarea 7.2), y esa guía es la que sigue el usuario. Ningún valor real de token se escribe en el repositorio, en los artefactos de OpenSpec ni en las evidencias: los comandos usan variables de entorno y, en los textos, marcadores como `<token>`. Los grupos 1 a 7 son locales y no se publican (`push`) hasta que el grupo 8 haya creado el secreto, porque el `push` a `main` despliega (véase el diseño, D9). Este cambio tiene comportamiento visible de API y de app: el grupo 9 es de QA. Las tareas de este cambio van después de las de `add-backend-ci-and-plain-logs`, y el cambio se archiva después de ese.
