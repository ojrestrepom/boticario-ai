# Plan de pruebas de la API y la CLI del catálogo

Cambio OpenSpec `add-catalog-backend`, commit `c4f7939`. Casos derivados de `specs/catalog-api/spec.md` (cada requisito y escenario) y de los requisitos observables desde la CLI de `specs/catalog-ingest/spec.md`, de las decisiones 16, 18, 19 y 21 de `design.md` y del contrato `backend/openapi.json`.

Herramientas: Newman 6.2.3 (`npx newman`) para la colección de escenarios principales; `curl`, `jq` y `sqlite3 -readonly` en scripts de shell para el resto (control de bytes, cabeceras y comparación con la base); Ajv 2020-12 para validar esquemas; shell para la CLI. La primera ejecución fue sobre el commit `c4f7939`; tras la corrección de los defectos (commit `7e13c1e`) se repitieron los casos afectados y toda la batería de regresión, con la evidencia nueva en `evidence/` con el sufijo `.rerun`.

Convenciones: el ID indica el bloque (`API` API en marcha con la base real, `ENV` arranque y copias de la base, `CLI` ingesta, `CONTRACT`, `NEWMAN`, `OPENAPI`, `CONC`, `NR` no ejecutados). La evidencia está en `evidence/` con el ID del caso como prefijo. El resultado obtenido es PASS, FAIL o NOT RUN.

Decisiones de producto que no se evalúan como defectos: nombres comunes con idioma `en`/`und` y texto literal, usos repetidos fundidos, familia `null` si la fuente no la trae, `checksum` extra en `/v1/sources`, campos `param` e `instance` en los errores, `limit` y `offset` ecoados, parámetros desconocidos ignorados, `q` limitado a 200 caracteres y 405 con `Allow: GET`.

## Resumen

Casos: 73. Primera ejecución (commit `c4f7939`): PASS 64, FAIL 5, NOT RUN 4. Re-ejecución tras las correcciones (commit `7e13c1e`): PASS 68, FAIL 0, NOT RUN 4, sin repetir 1 (CONC-001, que se mantiene en su resultado original).
